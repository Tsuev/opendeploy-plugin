# OpenDeploy: доступный агентский клиент

Этот сценарий работает только в среде, где агенту доступны файлы сайта, Node.js 22.13+ и команда запуска локального клиента. Не утверждай, что он уже доступен в обычном веб-чате ChatGPT или Claude: там может не быть доступа к файловой системе или выполнению команд. Для других сред нужна отдельная интеграция.

Клиент входит в плагин: `client/bin/opendeploy.mjs` относительно корня установленного плагина. Определи этот корень по расположению файла `skills/opendeploy/SKILL.md`, не относительно проекта пользователя. Для примеров ниже обозначим абсолютный путь к нему как `PLUGIN_ROOT`. Если зависимости клиента отсутствуют, выполни `npm ci --ignore-scripts --prefix "$PLUGIN_ROOT/client"` при наличии разрешения среды; если нет доступа на запись или в сеть, сообщи об этом. Не запускай нерассмотренные установочные скрипты и не придумывай инструменты.

1. Проанализируй проект и проведи базовую SEO-проверку согласно SKILL.md. Покажи найденные проблемы и согласуй изменения.
2. Установи, что итоговая сборка статическая, в её корне есть `index.html`, а в неё не включены секреты, скрытые файлы, ссылки и ненужные исходники. Проверь лимиты: один файл не более 10 МиБ, суммарно не более 25 МиБ файлов, не более 500 файлов и ZIP-архив не более 10 МиБ. Эти временные пределы задаются в клиенте; сервер также должен их применять. Сборка и работа сайта, которому нужен сервер, здесь не поддерживаются.
   До создания проекта выполни `node "$PLUGIN_ROOT/client/bin/opendeploy.mjs" review /абсолютный/путь/к/сборке`. Если клиент вывел предупреждение, остановись. Результат `requires_agent_review` означает, что нужно дополнительно проверить смысл страниц и все медиафайлы; он не является разрешением на публикацию. Если проверить содержимое нельзя или оно сомнительно, остановись и предупреди пользователя.
3. До выбора поддомена проверь доступ: запусти `node "$PLUGIN_ROOT/client/bin/opendeploy.mjs" projects`. Успешный ответ подтверждает доступ и даёт список проектов; повторно входить не нужно. Если сохранённого доступа нет или API отклонил его как недействительный, объясни, что нужно подключить OpenDeploy, и запусти `node "$PLUGIN_ROOT/client/bin/opendeploy.mjs" login`. Не считай сетевую ошибку или ошибку сервера отсутствием авторизации.
4. Передай пользователю именно адрес и код, выданные командой login, до её завершения. Объясни: на странице подключения нужно перейти ко входу и войти по почте или через Яндекс, если эти способы доступны; новый аккаунт создаётся при первом входе. Затем нужно вернуться по выданной ссылке, ввести код и подтвердить подключение. Не отправляй просто адрес панели вместо выданной ссылки, не проси пароль или токен в чат. Если появилась браузерная форма имени пользователя и пароля и пользователь не знает эти данные, не придумывай их: сообщи, что доступ к сервису требует выяснения, и остановись. Если вывод команды недоступен до её окончания, используй интерактивную сессию или сообщи об ограничении. После подтверждения повтори `projects`; только успешный ответ подтверждает доступ. Существующий проект выбирай только при подтверждённой связи с исходниками. Для нового проекта спроси желаемый поддомен, если пользователь его ещё не указал.
5. Для нового сайта выполни `check ИМЯ` через тот же путь к клиенту, чтобы проверить выбранный поддомен; если имя занято или недопустимо, попроси пользователя выбрать другое. Ошибка API означает, что доступность неизвестна. После успешной проверки создай проект командой `create "Название"`. Для повторной публикации уже закреплённое имя не проверяй как новое.
6. Покажи пользователю проект, содержимое итоговой сборки, выбранный адрес, известную стоимость и запроси подтверждение публичного размещения. После согласия и полной проверки допустимости содержимого выполни `deploy ID ИМЯ /абсолютный/путь/к/сборке --content-reviewed`. Клиент повторно проверяет сборку до отправки и останавливает публикацию при обнаружении запрещённых признаков.
7. Возвращай только фактический адрес из ответа. `published_local` — локальный предпросмотр; `ready_to_verify` с `availability: reachable` означает, что клиент смог открыть адрес, но не гарантирует индексацию. `availability: unverified` или ошибка — объясни, что доступность не подтверждена. Не обещай индексацию, пока сервис явно не подтвердил запуск.

По умолчанию клиент обращается к `https://app.opendeploy.ru`. Для локального прототипа можно задать `OPENDEPLOY_API=http://127.0.0.1:3100`. Доступность API зависит от фактической настройки сервера, DNS и HTTPS; не предполагай, что они уже запущены. Токен хранится локально в `~/.opendeploy/` и должен оставаться секретным; если среда не обеспечивает защищённого хранения, объясни ограничение.
